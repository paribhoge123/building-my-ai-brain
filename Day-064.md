# Day 064 — Handling Imbalanced Datasets

## 📌 Overview

A dataset is **imbalanced** when one class contains significantly more observations than another.

For example:

```text
Normal Transactions → 9,900
Fraud Transactions  →   100
```

Here:

```text
Majority Class → Normal
Minority Class → Fraud
```

Class imbalance is common in problems such as:

* Fraud detection
* Disease detection
* Spam detection
* Fault detection
* Rare-event prediction

---

# 1. The Accuracy Problem

Suppose a dataset contains:

```text
9,900 normal transactions
100 fraud transactions
```

A model predicts every transaction as normal.

It gets:

```text
9,900 correct
100 incorrect
```

Accuracy:

```text
99%
```

However, it detects:

```text
0 / 100 fraud cases
```

Therefore:

> High accuracy does not necessarily mean a good model when the classes are highly imbalanced.

---

# 2. Confusion Matrix

For binary classification:

```text
                    Predicted
                  Positive  Negative

Actual Positive     TP         FN
Actual Negative     FP         TN
```

Where:

* **TP** = True Positive
* **TN** = True Negative
* **FP** = False Positive
* **FN** = False Negative

For fraud detection:

```text
TP → Fraud correctly detected
TN → Normal transaction correctly identified
FP → Normal transaction incorrectly flagged as fraud
FN → Fraud incorrectly classified as normal
```

---

# 3. Precision

Precision answers:

> Of all examples predicted as positive, how many were actually positive?

```text
Precision = TP / (TP + FP)
```

High precision means that positive predictions are usually correct.

---

# 4. Recall

Recall answers:

> Of all actual positive examples, how many did the model detect?

```text
Recall = TP / (TP + FN)
```

High recall means that the model identifies a large proportion of actual positive cases.

---

# 5. F1 Score

F1-score combines precision and recall using their harmonic mean.

```text
F1 = 2 × (Precision × Recall)
     / (Precision + Recall)
```

It can be useful when both false positives and false negatives matter.

---

# 6. Class Weights

Class weighting tells the model to give more importance to minority-class mistakes.

For example:

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(
    class_weight="balanced"
)
```

For Random Forest:

```python
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(
    class_weight="balanced",
    random_state=42
)
```

`balanced` automatically adjusts class weights based on class frequencies.

---

# 7. Undersampling

Undersampling reduces the number of majority-class examples.

Example:

```text
Before:

Majority → 9,000
Minority → 1,000
```

After undersampling:

```text
Majority → 2,000
Minority → 1,000
```

### Advantage

* Smaller dataset
* Faster training

### Disadvantage

* Useful majority-class information may be discarded

---

# 8. Oversampling

Oversampling increases the number of minority-class examples.

Example:

```text
Before:

Majority → 9,000
Minority → 1,000
```

After oversampling:

```text
Majority → 9,000
Minority → 9,000
```

A simple approach is Random Oversampling, which duplicates minority examples.

### Advantage

* Majority-class information is preserved

### Disadvantage

* Repeated examples can increase overfitting

---

# 9. SMOTE

SMOTE stands for:

> **Synthetic Minority Over-sampling Technique**

Instead of simply duplicating minority examples, SMOTE creates synthetic examples based on existing minority observations and their neighboring points.

Conceptually:

```text
Existing minority samples → ●

Synthetic samples         → ○
```

SMOTE can be implemented using `imbalanced-learn`.

```python
from imblearn.over_sampling import SMOTE

smote = SMOTE(random_state=42)

X_resampled, y_resampled = smote.fit_resample(
    X_train,
    y_train
)
```

---

# 10. Important: Avoid Data Leakage

Do not apply SMOTE to the entire dataset before splitting.

### Incorrect

```text
Entire Dataset
     ↓
SMOTE
     ↓
Train/Test Split
```

### Correct

```text
Entire Dataset
     ↓
Train/Test Split
     ↓
Training Data
     ↓
SMOTE
     ↓
Train Model
```

The test set should remain untouched.

---

# 11. SMOTE with a Pipeline

Pipelines can be used to apply SMOTE correctly during Cross-Validation.

```python
from imblearn.pipeline import Pipeline
from imblearn.over_sampling import SMOTE
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("smote", SMOTE(random_state=42)),
    ("model", LogisticRegression())
])

pipeline.fit(X_train, y_train)
```

When used with Cross-Validation, the resampling can be performed within each training fold.

This helps prevent validation data from influencing the resampling process.

---

# 12. Comparing Techniques

| Technique     | Main Idea                            | Potential Issue                              |
| ------------- | ------------------------------------ | -------------------------------------------- |
| Class Weights | Penalize minority errors more        | Depends on model/data                        |
| Undersampling | Remove majority examples             | Information loss                             |
| Oversampling  | Duplicate minority examples          | Overfitting                                  |
| SMOTE         | Generate synthetic minority examples | Synthetic data may not always be appropriate |

---

# 13. Choosing Evaluation Metrics

The appropriate metric depends on the problem.

Possible metrics include:

* Accuracy
* Precision
* Recall
* F1-score
* ROC-AUC
* PR-AUC

For highly imbalanced problems, accuracy alone may hide poor minority-class performance.

The cost of false positives and false negatives should be considered when selecting evaluation metrics.

---

# 🧠 Key Takeaways

1. Class imbalance occurs when one class is much larger than another.
2. Accuracy can be misleading on imbalanced datasets.
3. Precision measures how reliable positive predictions are.
4. Recall measures how many actual positives are detected.
5. F1-score combines precision and recall.
6. Class weights can increase the importance of minority-class errors.
7. Undersampling reduces majority-class examples.
8. Oversampling increases minority-class examples.
9. SMOTE generates synthetic minority examples.
10. Resampling should be performed only on training data.
11. Pipelines help apply resampling safely during Cross-Validation.
12. Metric selection should reflect the real cost of different errors.
