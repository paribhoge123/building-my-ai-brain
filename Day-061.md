# Day 061 — Machine Learning Pipelines

## 📌 Overview

A Machine Learning Pipeline is a sequence of data-processing and modeling steps that are executed in a fixed order.

A typical workflow might look like:

```text
Raw Data
   ↓
Preprocessing
   ↓
Feature Engineering
   ↓
Model Training
   ↓
Prediction
```

Scikit-learn provides the `Pipeline` class to combine these steps into one reusable workflow.

---

# 1. What is a Pipeline?

A pipeline connects multiple machine learning steps together.

For example:

```text
Data
 ↓
Scaling
 ↓
Model
```

Instead of manually applying each step, we can define them in a pipeline.

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])

pipeline.fit(X_train, y_train)

predictions = pipeline.predict(X_test)
```

---

# 2. Why Use Pipelines?

Pipelines provide several advantages:

* Cleaner code
* Reproducible workflows
* Easier model deployment
* Easier integration with Cross-Validation
* Reduced risk of preprocessing mistakes
* Help prevent data leakage

---

# 3. Data Leakage

Data leakage occurs when information from outside the training data is unintentionally used during model training.

For example, suppose we scale the entire dataset before splitting it:

```text
Entire Dataset
      ↓
Calculate mean/std
      ↓
Scale data
      ↓
Train/Test Split
```

The scaling step has used information from the future test set.

This can result in overly optimistic evaluation.

---

# 4. How Pipelines Help Prevent Leakage

With a pipeline:

```text
Training Data
      ↓
Fit Scaler
      ↓
Transform Training Data
      ↓
Train Model
```

For unseen data:

```text
Test Data
      ↓
Use fitted Scaler
      ↓
Transform
      ↓
Predict
```

The scaler learns its parameters only from the training data.

---

# 5. Pipeline + Cross-Validation

Pipelines are especially useful with Cross-Validation.

Suppose we use 5-fold CV.

For every fold:

```text
Training Fold
      ↓
Fit Preprocessing
      ↓
Transform
      ↓
Train Model
      ↓
Validation Fold
      ↓
Evaluate
```

The preprocessing is fitted separately inside each training fold.

This prevents information from the validation fold from leaking into preprocessing.

---

# 6. Pipeline + Grid Search

Pipelines can also be combined with hyperparameter tuning.

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])

param_grid = {
    "model__C": [0.01, 0.1, 1, 10]
}

grid_search = GridSearchCV(
    pipeline,
    param_grid,
    cv=5,
    scoring="accuracy"
)

grid_search.fit(X_train, y_train)

print(grid_search.best_params_)
print(grid_search.best_score_)
```

---

# 7. Understanding `model__C`

Our pipeline contains:

```text
scaler
model
```

The Logistic Regression model has a hyperparameter called:

```text
C
```

Therefore:

```python
"model__C"
```

means:

> Tune the `C` parameter of the pipeline's `model` step.

The syntax is:

```text
step_name__parameter_name
```

---

# 8. Multiple Pipeline Steps

A pipeline can contain multiple transformations.

For example:

```text
Raw Data
   ↓
Missing Value Imputation
   ↓
Scaling
   ↓
Feature Selection
   ↓
Model
```

Possible Scikit-learn components include:

* `SimpleImputer`
* `StandardScaler`
* `MinMaxScaler`
* `OneHotEncoder`
* `PCA`
* Feature selection methods
* Machine learning models

---

# 9. Manual Processing vs Pipeline

| Manual Processing                   | Pipeline                |
| ----------------------------------- | ----------------------- |
| More code                           | Cleaner code            |
| Easier to make mistakes             | More systematic         |
| Leakage is easier to introduce      | Helps prevent leakage   |
| Harder to reproduce                 | Reproducible            |
| CV preprocessing can be complicated | Works naturally with CV |

---

# 10. Correct Workflow

A good ML workflow is:

```text
Raw Data
   ↓
Train/Test Split
   ↓
Pipeline
   ↓
Cross-Validation
   ↓
Hyperparameter Tuning
   ↓
Best Model
   ↓
Final Test Evaluation
```

The test set should remain separate until final evaluation.

---

# 🧠 Key Takeaways

1. A Pipeline combines multiple ML steps into one workflow.
2. Pipelines make code cleaner and more reproducible.
3. They help prevent data leakage.
4. They work naturally with Cross-Validation.
5. Pipelines can be combined with Grid Search and Random Search.
6. Pipeline parameters can be accessed using `step__parameter`.
7. Preprocessing should be fitted only using training data.
8. Pipelines are an important part of production-ready ML workflows.
