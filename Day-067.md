# Day 067 — Machine Learning Model Deployment Basics

## 📌 Overview

Training an ML model is only one part of building a real-world machine learning application.

A deployed ML system must take new input, process it correctly, pass it through the trained model, and return a prediction.

This lesson introduces the fundamentals of:

* Training vs inference
* Saving ML models
* Loading models
* Saving preprocessing pipelines
* Creating prediction APIs
* FastAPI
* Connecting ML services with backend applications
* Basic ML deployment architecture
* Model versioning
* The ML lifecycle

---

## 1. Training vs Inference

### Training

The model learns patterns from training data.

```text
Training Data
      ↓
Algorithm
      ↓
Learn Parameters
      ↓
Trained Model
```

### Inference

The trained model makes predictions on new data.

```text
New Input
    ↓
Trained Model
    ↓
Prediction
```

Training usually happens separately from prediction.

---

## 2. Why Don't We Train the Model for Every Request?

Suppose an application receives thousands of requests.

We don't want:

```text
Request
   ↓
Train Model
   ↓
Predict
   ↓
Response
```

Instead:

```text
Train Model
    ↓
Save Model
    ↓
Deploy Model
    ↓
Reuse Model for Predictions
```

The model is trained once and then used for inference.

---

## 3. What Is Model Deployment?

Model deployment means making a trained model available so that new data can be sent to it and predictions can be returned.

For example:

```http
POST /predict
```

Request:

```json
{
  "age": 35,
  "income": 70000,
  "credit_score": 720
}
```

Response:

```json
{
  "prediction": 1
}
```

The ML model is now being served as part of an application.

---

## 5. Saving a Scikit-Learn Model

After training:

```python
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier()

model.fit(X_train, y_train)
```

The model can be saved using `joblib`:

```python
import joblib

joblib.dump(model, "model.pkl")
```

This creates:

```text
model.pkl
```

which contains the trained model.

---

## 6. Loading the Model

The deployed application can load the model:

```python
import joblib

model = joblib.load("model.pkl")
```

The model can now be used for inference.

---

## 7. Save the Preprocessing Too

Suppose training uses:

```text
Raw Data
   ↓
Scaling
   ↓
Model
```

The exact same preprocessing must be applied during inference.

Correct:

```text
New Data
   ↓
Same Scaling
   ↓
Model
```

Using a newly fitted scaler or different preprocessing can produce incorrect predictions.

---

## 8. Using a Pipeline

A scikit-learn pipeline can combine preprocessing and the model.

```python
from sklearn.pipeline import Pipeline

pipeline = Pipeline([
    ("scaler", scaler),
    ("model", model)
])
```

Train it:

```python
pipeline.fit(X_train, y_train)
```

Save it:

```python
import joblib

joblib.dump(pipeline, "model_pipeline.pkl")
```

Load it:

```python
pipeline = joblib.load("model_pipeline.pkl")
```

Predict:

```python
prediction = pipeline.predict(new_data)
```

This is safer because the preprocessing and model stay together.

---

## 9. Creating an ML API

A Python framework commonly used for serving ML models is FastAPI.

Basic structure:

```text
ml-service/
│
├── app.py
├── model_pipeline.pkl
└── requirements.txt
```

Basic API:

```python
from fastapi import FastAPI
import joblib

app = FastAPI()

model = joblib.load("model_pipeline.pkl")

@app.get("/")
def home():
    return {"message": "ML API is running"}
```

---

## 10. Prediction Endpoint

Example:

```python
from fastapi import FastAPI
from pydantic import BaseModel
import joblib

app = FastAPI()

model = joblib.load("model_pipeline.pkl")


class UserInput(BaseModel):
    age: float
    income: float
    credit_score: float


@app.post("/predict")
def predict(data: UserInput):

    input_data = [[
        data.age,
        data.income,
        data.credit_score
    ]]

    prediction = model.predict(input_data)[0]

    return {
        "prediction": int(prediction)
    }
```

The model is now accessible through an HTTP API.

A full-stack application can use:

```text
React
   ↓

   ↓
```

## 13. Example: AI Resume Analyzer

A possible architecture:

```text
                  React
                    ↓
              Node / Express
              ↙           ↘
         MongoDB       Python ML API
                           ↓
                     ML/NLP Model
                           ↓
                    Resume Analysis
```

The ML service returns something like:


## 14. Model Versioning

Models can change over time:

```text
model_v1
model_v2
model_v3
```

Different versions may use:

* Different training data
* Different features
* Different algorithms
* Different hyperparameters

Knowing which model version is running is important for debugging and reproducibility.

---

## 15. Security and Input Validation

A deployed ML API should validate incoming data.

Important checks include:

* Data types
* Required fields
* Missing values
* Valid ranges
* Unexpected inputs
* Authentication where required

For example:

```text
age = -500
```

should not silently be passed into a model.

---

## 16. Local vs Production

During development:

```text
React       → localhost:3000
Node.js     → localhost:5000
FastAPI     → localhost:8000
```

In production, these services can be deployed separately or together depending on the architecture.

Deployment also requires consideration of:

* CPU
* RAM
* Storage
* Dependencies
* Startup time
* Latency
* Scaling
* Logging
* Model files
* Environment variables

---

## 🧠 Key Takeaways

* Training and inference are different stages.
* A trained model should usually be saved rather than retrained for every request.
* Preprocessing must remain consistent between training and inference.
* Pipelines help bundle preprocessing and the model together.
* ML models can be exposed through APIs.
* FastAPI is commonly used for Python ML services.
* Node.js and Python can work together in a full-stack ML application.
* Model versioning helps maintain reproducibility.
* Input validation is important for production ML APIs.
* Deployment is only one part of the larger ML lifecycle.
