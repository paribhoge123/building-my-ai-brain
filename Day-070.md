# 🚀 Day 070 — ML Model Monitoring, Logging & Data Drift

## 1. Introduction: Why Do We Need Model Monitoring?

Imagine building a Machine Learning model that predicts house prices.

During testing:

* Accuracy: 95%
* Predictions: Very good
* Model performance: Excellent

After deploying it, the model starts receiving new data. Over time, property prices, customer preferences, and housing trends change.

The model still uses its old training knowledge, so its predictions may become inaccurate.

This is why deploying a model isn't the end of Machine Learning.

**Model Monitoring** is the continuous process of tracking a deployed ML model to ensure that it performs correctly and produces reliable predictions.

We generally monitor:

* Model performance
* Input data quality
* Prediction distribution
* Response time
* Errors and failures
* Data and model drift

## 2. What Is Logging?

Logging means recording important events and information while an application runs.

For example:

```text
2026-11-01 10:30:00 - Prediction request received
2026-11-01 10:30:01 - Model prediction: Setosa
2026-11-01 10:30:01 - Request completed successfully
```

### Types of Logs

**1. Application Logs**

Record application activities, errors, and events.

**2. Prediction Logs**

Record prediction-related information, such as prediction IDs, timestamps, and model versions.

**3. Performance Logs**

Record response time, memory usage, CPU usage, and other performance metrics.

**4. Error Logs**

Record exceptions, failed requests, and service failures.

### Python Logging Example

Python provides a built-in `logging` module.

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - %(message)s"
)

logging.info("ML application started")
logging.warning("Input value is outside expected range")
logging.error("Prediction failed")
```

### Why Is Logging Important?

* Helps debug errors.
* Helps understand application behavior.
* Helps investigate unexpected predictions.
* Helps identify performance problems.
* Provides useful information for monitoring.

**Important:** Avoid logging passwords, API keys, personal information, or unnecessary sensitive user data.

## 3. What Is Data Drift?

Suppose we trained a house price prediction model using this dataset:

| Feature            | Training Data |
| ------------------ | ------------: |
| Average house size | 1,000 sq. ft. |
| Average house age  |      10 years |
| Average price      |      ₹40 lakh |

After two years, we receive new data:

| Feature            |      New Data |
| ------------------ | ------------: |
| Average house size | 1,800 sq. ft. |
| Average house age  |       5 years |
| Average price      |      ₹75 lakh |

The characteristics of incoming data have changed significantly.

**Data Drift** occurs when the statistical distribution of incoming production data changes compared with the training data or an established baseline.

Examples:

* Customer age distribution changes.
* Average product prices increase.
* Customer purchasing patterns change.
* User behavior changes.

## 4. Types of Drift

### A. Data Drift (Covariate Drift)

Data drift occurs when the distribution of input features changes.

Example:

Training data:

```text
Average customer age = 25
```

Production data:

```text
Average customer age = 40
```

Mathematically:

$$
P_{\text{train}}(X) \neq P_{\text{production}}(X)
$$

Here, X represents input features.

### B. Concept Drift

Concept drift occurs when the relationship between input features and the target variable changes.

Example:

A model predicts whether a customer will purchase a product.

Earlier, customers frequently purchased products after seeing discounts.

Now, customers are more influenced by product reviews.

The relationship between customer behavior and purchasing decisions has changed.

Mathematically:

$$
P_{\text{train}}(Y|X) \neq P_{\text{production}}(Y|X)
$$

Here:

* X = Input features
* Y = Target variable

### C. Prediction Drift

Prediction drift occurs when the distribution of model predictions changes.

Earlier:

```text
70% predictions = Approved
30% predictions = Rejected
```

Recently:

```text
20% predictions = Approved
80% predictions = Rejected
```

This may indicate a change in incoming data or model behavior.

However, prediction drift alone does not prove that model accuracy has decreased.

### Quick Comparison

| Type             | What Changes?                         |
| ---------------- | ------------------------------------- |
| Data Drift       | Input distribution                    |
| Concept Drift    | Relationship between input and output |
| Prediction Drift | Distribution of predictions           |

## 5. What Is Model Drift?

Model drift is a broad term often used to describe declining model performance as real-world data or relationships change.

Example:

A spam detection model initially performs well.

But spammers continuously develop new techniques.

The model hasn't learned these new patterns, so its predictions become less reliable.

**Important:** Data drift does not automatically mean model performance has declined. Actual outcome labels are needed to evaluate whether prediction quality has changed.

## 6. How Can We Detect Data Drift?

### 1. Statistical Comparison

Compare training data with production data.

For numerical features:

* Mean
* Median
* Standard deviation
* Distribution

For categorical features:

* Category frequencies
* Category proportions
* New or missing categories

### 2. Population Stability Index (PSI)

PSI measures how much a population distribution has changed between two datasets.

Commonly used interpretation:

* PSI < 0.1: Little change
* PSI between 0.1 and 0.25: Moderate change
* PSI > 0.25: Significant change

These are common guidelines, not universal rules.

### 3. Kolmogorov-Smirnov Test (KS Test)

The KS test compares two distributions.

It is commonly used to determine whether two numerical samples may come from different distributions.

### 4. Evidently AI

Evidently is a Python library used for evaluating and monitoring ML systems.

It can help identify:

* Data drift
* Data quality issues
* Model performance changes
* Prediction distribution changes

Documentation: https://docs.evidentlyai.com/

## 7. Practical Example — Detecting Data Drift Using Python

Generate two datasets:

* Reference data: Original training baseline.
* Current data: Newly arriving production data.

```python
import numpy as np
import pandas as pd

np.random.seed(42)

# Original training data
reference_data = pd.DataFrame({
    "age": np.random.normal(25, 5, 1000)
})

# New production data
current_data = pd.DataFrame({
    "age": np.random.normal(40, 8, 1000)
})

print("Reference Mean:")
print(reference_data["age"].mean())

print("\nCurrent Mean:")
print(current_data["age"].mean())
```

Expected observation:

```text
Reference Mean: Approximately 25
Current Mean: Approximately 40
```

The average customer age has changed significantly.

This is a possible indication of data drift.

### Visualizing the Difference

```python
import matplotlib.pyplot as plt

plt.hist(
    reference_data["age"],
    bins=30,
    alpha=0.5,
    label="Reference Data"
)

plt.hist(
    current_data["age"],
    bins=30,
    alpha=0.5,
    label="Current Data"
)

plt.xlabel("Age")
plt.ylabel("Frequency")
plt.title("Data Drift Comparison")

plt.legend()
plt.show()
```

The resulting histogram should show differences between the two distributions.

This is a simple demonstration. Real projects should use suitable statistical tests or drift-detection methods rather than relying only on the mean or a histogram.

## 8. What Happens When Drift Is Detected?

A typical workflow:

1. Detect a change in incoming data.
2. Investigate which features have changed.
3. Check whether model performance has declined.
4. Collect recent, representative, correctly labelled data.
5. Retrain or update the model if necessary.
6. Evaluate the new model against the existing model.
7. Deploy the updated model if it meets the required criteria.
8. Continue monitoring.

**Important:** Never retrain a model automatically just because drift is detected. First investigate whether the change is meaningful and whether retraining is actually needed.

## 10. Key Takeaways

1. Model monitoring tracks the health of deployed ML models.
2. Logging records application events and prediction-related information.
3. Data drift occurs when incoming input data distributions change.
4. Concept drift occurs when the relationship between inputs and outputs changes.
5. Prediction drift occurs when the distribution of predictions changes.
6. PSI and KS tests can help detect distribution changes.
7. Retraining may be necessary when model performance degrades.

Machine Learning doesn't end when a model is deployed.

A good ML engineer must also understand how to monitor, maintain, evaluate, and improve that model over time.
